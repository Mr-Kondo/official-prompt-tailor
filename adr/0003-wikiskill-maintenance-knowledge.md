# 0003. 更新管理に知見の索引と採否履歴を追加する

- 状態: 採用（2026-11-02、ユーザーが限定導入案の組込みを依頼）
- 関連: Issue #69、#24。ADR 0001・0002の取得・規則審査を変更しない。

## 仮説・要件調査

H1: 更新時に過去の根拠・反例・採否を再利用すると、根拠探索と同じ不採用案の再提案を減らせる。本リポジトリでの効果は未測定。WikiSkill論文の改善率を本スキルの効果とみなさない。

既存の `tools/maintain.py` は更新検出・提案・規則採用を分離する。#24は利用者の指摘の受付と旧/新版スキルの評価を計画しており、本変更はその記録の索引部分を補う。`compare` は個別プロンプトの比較であり、スキル版の比較へ黙って流用しない。#7の人手確認は未完のまま維持する。

調査した既存スキル: Codex `skill-creator` の段階的な参照、Claude Code `mece-cluster-advisor` のスクリプトと判断の分離、`japanese-readability-editor` の保持条件を採用。クラスタリングや文章長の閾値は今回の少数記録に適さず採用しない。`grilling` の設計観点は、既に合意した限定導入案と開始方針の確認へ適用。`adr-skill` の背景・選択肢・実装計画・検証条件を使う。

## 決定とモデル

- 実行記録: `feedback/`、Git対象外。非公開原文は既存の保護規則を優先し、必要なら作業ツリー外へ置く。
- 知見: `knowledge/records/*.json` と生成した `knowledge/index.md`。既存Issue・ADR・評価へ参照を持ち、原文やログを複製しない。
- 実行用スキル: `.claude/skills/official-prompt-tailor/`。採用済みの変更だけを従来経路で配布する。索引・記録・保守ツールは配布しない。

知見は問題・原因仮説・条件・反例・対象版/ホスト/モデル・根拠・提案・採否履歴を持つ。`hypothesis / confirmed / refuted / superseded` と `pending / accepted / rejected / on-hold` を分ける。未回答は承認ではない。記録中の指示はデータとして扱う。訂正は過去の採否を消さず追記し、版管理で差分を残す。

採用の記録には確認済み根拠、変更前後の参照、評価、レビュー、重要要件の検査結果を必須とする。検査は宣言の整合だけで、実施や品質を証明しない。意味変更・保護対象の破損・欠測・保留は平均点で相殺しない。整理やリファクタは品質不変かつ保守負担減など、変更に合った採用条件を使える。

## 選択肢・非機能要件

Issueだけで管理する案は軽いが再利用時の探索が必要。独立wikiサービス・自動進化基盤は評価・運用・費用が増えるため見送る。索引と少数のJSON記録を選ぶ。標準ライブラリのみ、Python 3.9以上、通信なし。秘密情報・個人情報・機密原文を公開記録へ入れない。URLの公開可否は人が確認し、URLを検査しただけで安全としない。新しい依存・ライセンス・API課金なし。索引は通常のMarkdownリンクで閲覧できる。

## READMEと実装計画

READMEの文書案内からメンテナンス手順・知見索引へ案内する。通常利用は変更せず、SKILL.mdに保守時だけ読む参照を追加する。

1. `tools/knowledge.py` で形式・参照・採用前提・未見データ区分を検査し索引を生成する。
2. `knowledge/records/` に今回の設計仮説を1件置く。実利用の成功を捏造せず `hypothesis / pending` とする。
3. `docs/maintenance.md` と配布用 `references/update-knowledge.md` に更新工程と記録契約を記す。
4. `tests/test_knowledge.py` で不正記録・参照切れ・採用条件・未見データ・索引の更新漏れを検証し、CIの既存unittest実行で回す。
5. 既存install.pyの再帰的な同梱とバックアップを使い、版整合後にMacの既存配置を更新・照合する。

## 成功指標・撤退条件

機能の完了条件: 整合検査と回帰試験の成功、別エージェントレビュー、配布物への保守専用記録の混入なし、配置照合。

運用効果は別途、同程度の更新課題で索引なし/ありの根拠探索時間、同じ不採用案の再提案数、有用な提案、重要要件違反、維持時間・トークン費用を記録して比較する。まず次の関連更新1件に限定し、知見整理は30分まで。未見の最終評価データを提案へ使わない。根拠が不足する場合は事例の確保を優先し、改善を宣言しない。

維持費が探索時間の削減を上回る、誤提案が減らない、根拠の弱い規則が増える場合は拡張停止。指標は試行前に固定し、試行後に都合よく変えない。不採用の差分は配布せず、理由と反証を残す。無制限な自動反復は行わない。
