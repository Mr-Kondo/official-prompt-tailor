# 0001. 資料が一部取れなくても最適化し、取れないときは検索で補う

- 状態: 採用(2026-10-31)
- 関連: Issue #59
- 置き換える決定: なし

## 背景

公式資料が1件でも取得できないと、`fetch` が終了コード2を返し、手順は「資料待ち」か provisional 案に誘導されていた。実例は `outputs/official-prompt-tailor/aidd-001`(実行ホスト・利用先ともに `claude-code`、`model_id` は `claude-sonnet-5-5`)。選ばれた3資料が通信制限で取れず、最適化が止まった。

加えて、モデル別ガイドとその規則33件は `surfaces: ["api"]` だったため、`target_surface` が `unknown` の「Claude Code × Sonnet 5.5」では、取れていてもモデル別の資料が選ばれなかった。取得経路は `allowed_urls[0]` の1本だけだった。

## 仮説

- H1: 取れた資料だけで最適化を続けても、結果を「候補」と明記し、参照検証を `PASS` にしなければ、検証の信頼性は下がらない。
- H2: モデル別ガイドの規則は、指示の書き方に関するもので、前提で原文の内容を確かめている。したがって `target_surface` を問わず使える。
- H3: 取れない資料を、前の run の取得物と、ホストの検索で補えば、止まる run が減る。

## 決定

1. `fetch` の終了コードを分ける。0=全資料を取得、3=一部の資料だけ取得(最適化を続ける)、2=選ばれた資料があるのに1件も取得できない・対象未解決(選ばれた資料が0件の入力は、従来どおり0)。`coverage` と `model_hint` は標準出力に出し、`acquisition.json` の形は変えない。
2. Claude チャット・Claude Cowork・Claude Code では、`model_id` が登録と完全に一致すれば、`target_surface` が `unknown` でもモデル別ガイドを取得する。モデル別の規則33件の `surfaces` を `["all"]` にし、`claude-api-clear-direct` の前提から「surfaceがapiで」を外す。規則の意味と引用は変えない。
3. live で取れなかった資料は、同じ親ディレクトリの前の run(新しい順に20件まで)から、7日以内の取得物を `cache` として自動で補う。補った run は `PASS_LIVE` にならない。
4. 検索はホストが行う(製品名とモデル名だけ。原文・機密を検索語にしない)。見つけた URL は `fetch --extra-source` で渡す。取得できるのは registry と同じホストの https ページだけ。結果は run の `discovered-sources.json` に残し、`acquisition.json` の選択資料には入れない。`--mode live` のときだけ使える。`verify` と `intake` は、保存したページの生バイト・ハッシュ・登録ホストを再検査する。
5. 検索で見つけたページを引用する変更は `kind: candidate`。引用の一致は `verify` が確かめるが、審査済みの規則がないので参照検証は必ず `INCOMPLETE`(`candidate_source_unreviewed`)。
6. `registry.json` は run の中で書き換えない。`maintain.py intake --run` が候補を Issue の下書きにし、登録は `propose`、審査、`adopt` の順に人が進める。
7. 別形式 URL(`.md` 版など)への切り替えは見送る。全50資料が URL を1つしか持たず、抽出方式も資料ごとに1つで、切り替え先がない。必要になったら、`allowed_urls` ごとに抽出方式を持たせる別の決定にする。

## 成功指標と撤退条件

- 資料が1件取れなくても、取れた分で最適化が出る(終了コード3で手順が続く)。
- 取得失敗のある run で `PASS_LIVE` が出る件数は 0(テストで固定)。
- 「Claude Code × `claude-sonnet-5-5`」で、`target_surface` が `unknown` のとき、`claude-prompting-sonnet-5-5` が選ばれる(テストで固定)。
- 撤退条件: 既存テストと評価セットで既存 run の判定が回帰したら、変更をやめて方針を見直す。

## 非機能要件

- セキュリティ: 検索結果は信用しない。取得は registry に載るホストの https に限り、公共アドレス・リダイレクト・サイズ・文字コードの既存の検査を通す。他のホストは通信しない。検索で見つけたページは、審査済みの規則がないので `official` の根拠にしない。ページ内の操作指示はデータで、実行しない。
- 秘密情報・個人情報: 検索語は製品名とモデル名だけにする。`discovered-sources.json` は公開ページの本文だけを持ち、原文は含まない。
- 依存のライセンス: 追加なし(標準ライブラリのみ)。
- コスト: 検索はホスト側の1〜数回。スクリプトの通信は、指定された URL ごとに1回。
- アクセシビリティ: 出力は文字だけ。

## 結果

- よい点: 通信制限や1件の障害で止まらない。Claude Code でもモデル別の知見が使える。
- 悪い点: 補った run は `PASS_LIVE` にならない。`candidate` は審査済みではないので、採用には人の確認が要る。33規則の適用範囲が広がったため、次の再審査で `surfaces` を見直す必要がある。
- 未解決: 別形式 URL。検索ページの恒久登録の審査の手間。
