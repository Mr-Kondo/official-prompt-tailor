`v0.1.4` からの変更は、`drift` と `discover` の追加、その週次の自動実行、Windows の不具合の修正です。添付の ZIP は、4 ファイルが `v0.1.4` と異なります。ほかの 2 ファイルは同じです。

## 変更点
スキル本体(添付の ZIP に入るもの):
- `scripts/evidence.py` に `drift` を追加しました。資料の本文が、規則を審査したあとで変わったかを、本文のハッシュと引用の有無で調べます。意味が変わったかは判定しません。`--run <run>` を付けると、その run の取得結果を使い、通信しません。
- `SKILL.md` の手順 3 を変えました。規則を選ぶ前に `drift --run` を実行します。`changed` と `excerpt_missing` の規則は、根拠にしません。
- HTML の本文から、相対時刻の行(`Updated 3 days ago` など)を除くようにしました。記事が更新されなくても、毎日変わってハッシュが動くためです。
- `fetch` の `--out` が、Windows の Python 3.9 で、まだない相対パスを拒否していた不具合を直しました。
- `references/registry.json`:
  - どの利用先にも、どの規則にも使われていなかった資料 `claude-prompting-overview` を削除しました(資料は 20 件から 19 件)。
  - 資料の本文が変わった規則 3 件を再審査して、審査の記録(`source_body_sha256`、`reviewed_at`、`reviewer_id`)を更新しました。対象は `claude-cowork-describe-task`、`claude-cowork-check-modes`、`claude-code-skill-frontmatter` です。再審査したのは Claude Code のエージェントで、人ではありません。
- `references/evidence-contract.md` に、`drift` の仕様を書きました。

保守用(ZIP には入らないもの):
- `tools/maintain.py` を追加しました。`discover` は、各公式サイトの `llms.txt` から、まだ登録していない新規ページの候補を挙げます。取得できなかった一覧は、2 秒待って 1 回だけ取り直します。`propose` は、候補の URL を、`sources` に足せる登録案にします。
- GitHub Actions を追加しました。
  - `test`: push と pull request で、テストを実行します。Ubuntu 24.04 では Python 3.9〜3.14、macOS と Windows では 3.9 と 3.14 を使います。
  - `watch`: 毎週月曜 03:17(UTC)に、`drift` と `discover` を実行します。人の判断が要る結果だけを、Issue にします。
  - `release`: タグ `v*` を push すると、Release を作ります。
- Windows で失敗していたテストを直しました(文字コード、改行、開いたままの ZIP)。`.gitattributes` で改行を LF にそろえ、`install.py` の自己点検も UTF-8 で読むようにしました。
- `docs/maintenance.md` に、更新の確かめ方、新しい資料の見つけ方と足し方、自動実行、リリース手順を書きました。
- `--plugin` が作るマニフェストの `version` を `0.2.0` にしました。

## 確認できていること
- テスト 144 件が通ります(ネットワークは mock)。Python 3.9.6、3.10.22、3.11.17、3.12.15、3.13.16、3.14.8、3.15.0 で確認しました。
- GitHub Actions の `test` は、全 10 ジョブが成功しました。内訳は、Ubuntu 24.04 が 6、macOS が 2、Windows が 2 です。
- 実際の公式サイトに対して、`drift` を実行しました(2026-10-15、`watch` の手動実行 2 回)。登録した 19 資料をすべて取得でき、判定は `CURRENT`(審査後に変わった規則なし)でした。
- `discover` を実行しました(2026-10-15)。公式サイト 7 か所の一覧をすべて取得でき、新規ページの候補は 59 件でした。
- `watch` の 2 回目の実行で、既存の Issue の本文が置き換わることを見ました。コメントは増えませんでした。
- 添付の ZIP は、`v0.1.4` の ZIP と比べて、上の 4 ファイルだけが違います。

## 確認できていないこと・既知の問題
- `release` の workflow は、このタグの push が初回の実行です。事前には動かしていません。
- `watch` と `release` は `ubuntu-latest` で動きます。`ubuntu-latest` は、2026-10-19 から Ubuntu 26 へ移り始めます。Python 3.12 のビルドはあるはずですが、移行後の実行は確かめていません。`test` だけは、Python 3.9 に Ubuntu 26.04 のビルドがないため、Ubuntu 24.04 に固定しています。
- 実際の依頼では、`SKILL.md` の手順 3 を試していません。規則を選ぶ前に `drift --run` を実行する流れです。`drift` コマンドとしては、テストと実サイトで動かしました。
- `discover` が挙げた候補 59 件は、採用するか見送るかを決めていません([Issue #1](https://github.com/Mr-Kondo/official-prompt-tailor/issues/1))。Claude の新しいモデルごとのプロンプトガイドなど、公式のページが、まだ登録されていません。
- 規則 34 件の審査は、すべて Claude Code のエージェントが行ったもので、人の審査ではありません。
- Python 3.9 と Windows で、実際のネットワークに出る取得(live)は動かしていません。テストはネットワークを mock しています。
- 以下は `v0.1.4` から変わっていません。
  - `openai-api-prompting`(`developers.openai.com`)は、ボット検査で HTTP 403 になる時間帯があります。`drift` は、この資料を「確認できない」として扱い、`INCOMPLETE` にします。2026-10-15 の実行では取得できました。
  - Claude Cowork と ChatGPT Work では動かしていません。ChatGPT Work へのプラグインの取り込み方は、公式資料で確認できていません。
  - 読取りの観測ができるのは Claude Code だけです。他の製品では、参照検証は最良でも `INCOMPLETE` になります。
  - 意味審査と効果測定は未実施です。評価事例は `pending-review` のままです。
