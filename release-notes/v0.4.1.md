`v0.4.0` からの変更は、資料を、規則が使える入力にだけ取得するようにしたことと、ZIP を、どの機械でも同じバイト列で作るようにしたことです。添付の ZIP は、3 ファイル(`registry.json`、`evidence.py`、`evidence-contract.md`)が `v0.4.0` と異なります。ほかの 3 ファイル(`SKILL.md`、`recommendations-example.md`、`review-rubric.md`)は同じです。

**挙動が変わります。** `target_surface` と `model_id` が不明なとき、13 組(利用先 × `purpose`)で、取得される資料が 0 件になり、`verify` は `no_applicable_official_source` で `INCOMPLETE` にします。以前は、使える規則のない資料を読んで、`PASS_LIVE` になり得ました。使える規則そのものは変わっていません。

## 変更点
スキル本体(添付の ZIP に入るもの):
- `references/registry.json`:
  - 資料は、その入力で使える規則があるときだけ取得します。これまでは、規則のない入力でも資料を取得し、`verify` がその全行の読取りを求めていました(別のエージェントの確認で、`claude-chat-help` が 14 行読まれ、使える規則が 0 件だったのが、最初の所見です)。18 組(利用先 × 資料)の経路を、規則のある `purpose` だけに絞りました。
  - 使える規則は、利用先 × `purpose` × `target_surface` × `model_id` の全 1,188 入力で、変わりません。読む資料は、851 入力で延べ 846 件減りました。
  - `claude-model-prompting` を、規則の付く 4 モデル(`claude-fable-5-1`・`claude-opus-5-5`・`claude-sonnet-5-5`・`claude-haiku-5-5`)に限りました。これまでは、どのモデルでも取得されていました。モデル別の資料は、Claude の API の 9 件になりました。
  - 取得される資料がない組は、`docs/targets.md` の「使える規則の件数」で、17 組になりました。この変更で 13 組が加わりました。`target_surface` や `model_id` を指定すると、資料と規則が加わることがあります。
- `scripts/evidence.py`: `sources --markdown` の先頭に、見えない書式の版の行(`<!-- sources-report format 2 -->`)を足しました。
- `references/evidence-contract.md`: 上の行を書きました。

保守用(ZIP には入らないもの):
- `install.py --zip` が作る ZIP を、同じファイルから、どの機械でも同じバイト列にしました。ファイルを名前順に並べ、時刻・権限・作成元を固定し、圧縮しません。圧縮をやめたので、ZIP は 69,652 B から 296,668 B になりました。最後に `sha256:` を出します。タグから作り直した ZIP の sha256 を、公開された ZIP の `digest` と比べると、ダウンロードせずに確かめられます(`docs/maintenance.md` の「公開した ZIP を確かめる」)。
- `tools/maintain.py`:
  - `registry_problems` に、経路と規則の検査を足しました。使える規則のない資料を取得する経路と、どの入力でも使えない規則を拒否します。`adopt` も同じ検査を通ります。
  - `audit` は、貼られた報告の書式の版を見ます。版が違う報告は、照合できないので `WARN` にします(これまでは、書式を変えると、古い記録がすべて `FAIL` になりました)。
  - `docs/targets.md` のモデル別の表を、モデルごとの行にしました。
- `.github/workflows/test.yml`: 各ジョブが、ZIP の sha256 を出します。
- `--plugin` が作るマニフェストの `version` を `0.4.1` にしました。
- docs: 手書きの説明を、新しい経路に合わせました。
- テストを 206 件から 212 件にしました。
