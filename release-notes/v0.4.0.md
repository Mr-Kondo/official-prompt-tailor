`v0.3.0` からの変更は、どの資料を、なぜ、モデルに応じてどう選んで見たかを、スクリプトだけで確かめる `sources` と、規則の審査者の表示、サブエージェントの記録の読み取りです。別のモデルのエージェントに手順を通させ、その所見で SKILL.md を直しました。添付の ZIP は、4 ファイルが `v0.3.0` と異なります。ほかの 2 ファイル(`registry.json`、`review-rubric.md`)は同じです。

## 変更点
スキル本体(添付の ZIP に入るもの):
- `scripts/evidence.py`:
  - `sources` 副コマンドを追加しました。実行の前は、`--target`・`--surface`・`--model`・`--purpose`(または `--input`)で、選ばれる資料と、選ばれない理由を出します(通信しません)。`--all-models` は、モデルごとに加わる資料です。実行の後は、`--run` で、選んだ資料、取得した本文のハッシュが記録と合うか、引用した規則とその審査者、`--host-log` を渡せば生成の前に読んだ行を出します。判定は `CONSISTENT` / `INCONSISTENT` / `INCOMPLETE`(終了コード 0 / 1 / 2。計画は 0)です。`--markdown` は、同じ内容をスクリプトが Markdown にします。
  - モデル別の資料があるのは、Claude の API の 8 件だけです(`target_surface` が `api` で、`model_id` が完全に一致するときだけ選ばれます)。ほかの利用先では、`model_id` を変えても資料は変わらず、報告がそう書きます。`model_id` の綴り違い(日付の付いた ID など)は、登録済みの ID をヒントに出すだけで、選択には使いません。
  - `rules` の出力に、規則ごとの `reviewer_id`、`human_reviewed`、`surfaces`、`models` と、件数の `review` を足しました。`human:` で始まる `reviewer_id` だけが人の審査です。`human:` のあとが空の `reviewer_id` は、registry の検査が拒否します。
  - サブエージェントの記録(全メッセージが `isSidechain` で、1 つの `agentId` を持つファイル)を、そのエージェント自身の記録として全体を読みます。これまでは全部捨てていたため、サブエージェントが動かしたスキルの読取りを観測できませんでした。メインの記録の中の sidechain は、これまでどおり読みません。JSON だが記録ではない行で落ちる不具合も直しました。
  - `select_sources` を `route_sources` に分け、選ばれなかった理由を返す `explain_sources` を足しました。選ぶ結果は変わりません(テストが、利用先 × `purpose` × `surface` × モデルの全組み合わせで固定しています)。
- `SKILL.md`: 別のエージェントの所見を反映しました。`target_surface` と `model_id` の値と調べ方、選ばれた資料はすべて読むこと、`verify` は通信しないこと、`assess` は審査を記録したときだけ実行すること、最終回答に `sources --markdown` の標準出力を添えること、ほか。
- `references/evidence-contract.md`: `sources` の仕様と、`rules` の出力を足しました。
- `references/recommendations-example.md`: 書くときの注意を足しました。差分の全区間を変更の区間で覆うこと、追記だけの変更の書き方、行範囲と引用の関係、規則が複数あるときの選び方です。
